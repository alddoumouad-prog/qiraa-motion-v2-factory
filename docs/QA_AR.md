# الجودة — ما يتم اختباره وما لا يتم

## إلزامي لكل حلقة

1. المصدر الصحيح: التاريخ والسياق والمعلومات والمصدر الإضافي عند الحاجة؛ الحقوق لا تثبت بمجرد النسبة.
2. افتح الفيديو فعليًا. شاهد الافتتاحية والبطاقات والمداخلتين والخاتمة، وافحص الوجه وحواف الشاشة والنص العربي وحركة الفيديو. استخدم `contact_sheet.jpg` للمساعدة، لا باعتبارها بديلًا عن تشغيل الفيديو.
3. استمع للنهاية والبداية والمداخلتين والانتقالات. تحقق من أن التعليق مفهوم وأن صوت المصدر منخفض تحته، والـclick غير مزعج، وأن مخرجات TTS لا تتخطى الكبسولة أو تشوّه الكلمات. إن تعذّر السماع صرّح به.
4. افحص `qa_report.json`: الفيديو 1080×1920، 840 إطارًا، 30fps، 28ث، وفك المحتوى دون أخطاء. افحص `loudness.txt` للقياس الفعلي. لا يُعد الهدف النظري التزامًا بمستوى صوت بعينه بعد الترميز.
5. راجع التوقيتات الفعلية للكلمات مع التفريغ وليس النص المكتوب وحده. انظر `audio_events` للفترات والسرعات. إن كان الصوت أسرع من الطبيعي اختصر النص أو غيّر التوقيت بدل الاعتماد على الحد الأقصى 1.6×.
6. سلّم ملف MP4 وتقريرًا قصيرًا وروابط المصدر. إذا كانت الحقوق غير مؤكدة فالتسليم مسودة داخلية فقط.

## الفحص الآلي المطبق

- يرفض حقولًا ناقصة، روابط غير HTTP، مسارات خارج المستودع، IDs مكررة، نوافذ متداخلة، مداخلات لا تطابق كلمات التفريغ، وبطاقات تحجب كبسولة.
- يرفض مصدرًا أقصر من 23.5ث بعد offset ومقاطع صوتية طويلة جدًا. يفك كل الملف النهائي ويقيس أبعاده ومدته، ويولّد لقطات من الملف النهائي ولوحة وتقرير صوت.
- لا يقيم صحة الخبر، ترخيص المصدر، دقة التفريغ، الجمال، طبيعية الصوت، أو ما إذا كان الوجه محجوبًا في جميع الإطارات. هذه مهام مراجعة فعلية وليست ضمانًا آليًا.

## اختبارات التطوير

```bash
python -m unittest discover -s tests -v
python factory/pipeline.py --validate-only --spec spec.json
```

تم اختبار إنتاج النموذج محليًا وتشغيل سير الإنتاج الأساسي على GitHub Actions؛ راجع تقرير الإصدار. نجح أيضًا اختبار رندر لمصدر ثانٍ في بيئة محلية دون GitHub Token؛ يلزم فحص كل نتيجة جديدة على حدة.
