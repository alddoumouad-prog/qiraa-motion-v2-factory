# مواصفة مشروع Motion V2 — spec.json

المثال التنفيذي الحقيقي في `../spec.json`، والمخطط الهيكلي المساعد `../spec.schema.json`. تحقق المصنع في `pipeline.py` هو المرجع التنفيذي؛ المخطط لا يختبر تداخل التوقيتات أو تطابق الكلمات أو الملفات. جميع التوقيتات بالثواني، والتوقيت صفر هو بداية الجزء المختار من الفيديو، لا بداية المنشور بالضرورة. المحرك ثابت على 28 ثانية؛ لا يوجد حقل مدة قابل للتغيير في هذا الإصدار.

## الحقول

| الحقل | المطلوب |
|---|---|
| `project_id` | معرّف فريد بأحرف إنجليزية صغيرة وأرقام و`-` أو `_`؛ يستخدم في اسم الملف. |
| `source_url` | رابط مباشر عام للمنشور/الفيديو، HTTP(S)، دون بيانات دخول. |
| `source_offset_seconds` | مقدار البداية داخل الملف الأصلي. يجب أن يحتوي المصدر على 23.5 ثانية متاحة بعده. |
| `source_credit` | نسبة موجزة صحيحة تظهر فوق الفيديو وفي الخاتمة؛ حد أقصى 90 حرفًا. |
| `location`, `date` | المكان الصحيح أو وصف محايد، وتاريخ **الحدث أو المنشور** بصيغة `DD.MM.YYYY` وفق السياق، لا تاريخًا مختلقًا. |
| `headline_lines` | ثلاثة أسطر عربية قصيرة على الأكثر 48 حرفًا لكل سطر. |
| `cards` | أربع بطاقات، لكل واحدة `kicker`, `value`, `sub`, `start`, `end`. كل بطاقة من 5.22 إلى 23.5 ثانية، مدتها ≥0.7ث، ولا تتقاطع مع بطاقة أخرى أو المداخلة. لا تختلق أرقامًا لملء البطاقات. |
| `narration` | ثلاثة مقاطع: `id`, `text`, `start`, `max_seconds`، و`audio_file` عند `pre_recorded`. |
| `micro` | مداخلتان: `id`, `text`, `start`, `max_seconds`, `anchor_word`, `anchor_end`، و`audio_file` عند `pre_recorded`. حد النص 45 حرفًا. الكبسولة دائمًا ثانيتان؛ صوتها داخل `max_seconds` ويجب أن يكون أقل من ثانيتين. |
| `tts.provider` | `pre_recorded` لاستخدام ملفات الصوت، أو `edge` لتوليدها؛ `fallback_voice` هو اسم صوت Edge عند اختيار `edge`. |
| `transcript_file` | مسار JSON لتفريغ كلماتي ملتزم داخل المستودع. `start`, `end` للكلمات بتوقيت الملف الأصلي (قبل طرح offset). |
| `editorial_review` | `facts_verified` لا يصبح true إلا بعد تحقق المحرر. `source_permission_confirmed` لا يصبح true إلا بعد تأكيد الحقوق. غيابه أو قيمته الخاطئة لا تمنح ترخيصًا. |

يمكن لكل مقطع صوتي إضافة `tempo` اختياري (مثل المثال)؛ المصنع يسرّع عند الحاجة لتناسب `max_seconds` ولا يبطئ المقاطع تلقائيًا، لكنه لا يقبل سرعة فوق 1.6×. الأفضل إعادة صياغة نص طبيعي قصير بدل السرعة العالية. مدة كل مقطع التي جرى توليدها تظهر في `qa_report.json`.

## قواعد التوقيت

- `micro.start` بين 5.25 و21.5 ثانية. يجب أن يبدأ عند نهاية `anchor_word` أو بعدها في حدود 0.12ث، ويطابق نهاية كلمة في التفريغ بعد طرح `source_offset_seconds`؛ لا تعتمد على التفريغ دون الاستماع إليه.
- مقاطع التعليق ومداخلات الصوت لا تتقاطع حتى ضمن حدود `max_seconds`. لا تظهر بطاقة خلال كبسولة المداخلة.
- الخط الرئيسي يظهر حتى 5.22ث؛ الكبسولة ثانيتان حتى لو كان صوتها أقصر. لا يتوقف الفيديو في فترة المداخلة.
- لأن النافذة قصيرة، قد يضطر الوكيل لاختيار اقتباس آخر من المصدر، أو إعادة كتابة نصوص موجزة. لا يختلق نقطة توقف أو يُسرع الكلام بصورة غير طبيعية. إن لم يوجد حل مناسب يطلب مصدرًا آخر أو يسلّم تشخيصًا واضحًا بدل الادعاء بالنجاح.
- التوقيتات تُفحص عدديًا لكنها لا تثبت وجود وقفة طبيعية ولا صحة الكلمة؛ يُراجعها محرر بالصوت.

## مصدر التفريغ

```json
[
  {"start": 0.14, "end": 5.54, "text": "… vote", "words": [
    {"start": 5.28, "end": 5.54, "word": " vote"}
  ]}
]
```

لو بدأ المقطع المستخدم من الثانية 2 من المصدر الأصلي، وكانت نهاية الكلمة عند 7.54 في التفريغ الأصلي، تكون `anchor_end` و`start` نحو 5.54 في spec. يجب مراجعة المخرجات المولدة آليًا.

## الملفات والمسارات

مسارات `audio_file` و`transcript_file` نسبية إلى جذر المستودع ولا يسمح الخروج منه. مع `pre_recorded`، يجب أن تكون ملفات MP3/WAV موجودة على الفرع قبل تشغيل Actions. لا تضع روابط أو مسارات ملف خارج المستودع داخل هذه الحقول. `--source` مخصص لاختبار محلي فقط؛ GitHub ينزّل من `source_url`. لا تُلصق رموز وصول في أي حقل. ضع كل مشروع جديد في مجلد فرعي مثل `projects/topic-001/` مع transcript وملفات الصوت وspec، ثم شغّل workflow باستخدام مسار ذلك spec.

## فحص سريع

```bash
python factory/pipeline.py --validate-only --spec projects/topic-001/spec.json
python factory/pipeline.py --spec projects/topic-001/spec.json
```

فحص `validate-only` لا يجلب الفيديو ولا يفحص الصوت الفعلي أو الحقوق. الرندر الفعلي يرفض الصوت الأطول من نافذته بعد حد التسريع ويتحقق من 1080×1920 و840 إطارًا ويُنتج لوحة مراجعة. احتفظ بنسخة من `used_spec.json` و`qa_report.json` مع التسليم.
